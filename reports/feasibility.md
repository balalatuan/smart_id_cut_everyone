# Phase 1 可行性与限制报告

这是 v0.1 的历史基线记录。v0.2 已更新大图输入和 15 KB 选项，见 large-images-v0.2.md；下文测试数字不代表升级后的复测。

## 结论

轻量的离线单图检测→估计→裁剪→压缩路径已在 Linux CPU 上实际运行；目前不能验证完整头发定位准确率，因此 Haar 仅是基线，不是最终生产模型选型。允许人工矩形修正，自动 PASS 关闭。

没有代表性私人照片，也没有独立人工标注。使用一张公开 NASA 人像、5 个同图变体、一张合成卡通、空白图和损坏文件，共 9 个 fixture。不同亮度和分辨率变体不算独立照片，**不满足 30–50 张独立样本的目标**。没有杜撰假 PASS 率或发际线误差。

## 候选方法比较（技术评估，不是四个模型的实测排名）

| 方法 | 能提供的内容 | 权重/许可/CPU约束 | 本次状态 |
|---|---|---|---|
| OpenCV Haar | 正面脸部框；不提供真实发际线/关键点 | 随 wheel 本地加载；OpenCV Apache-2.0，cascade 内嵌 Intel license；CPU 单线程、低安装门槛 | 已运行小样本基线 |
| OpenCV YuNet | 脸框和少量面部关键点；不提供头发轮廓 | 需额外 ONNX 权重，官方 Zoo 模型目录需检查对应许可；CPU DNN 可行，但必须测实机资源 | 未下载、未实测，优先下一轮候选 |
| MediaPipe Face Landmarker | 面部网格、姿态相关信息；网格不等于完整头部 | 需任务权重并确认所选版本、平台 wheel、模型条款；CPU 可运行，但当前 Intel Mac 内存/精度未测 | 未安装、未实测 |
| 本地头发/人物分割模型 | 仅在类别设计支持时才有头发/头部 mask | 通用人像分割常只有前景，不区分头发；脸部解析模型需核对训练域、许可证、权重来源和 RAM | 未选定权重，无分割精度声明 |

FaceDetector 可注入测试或后续真实检测器；Geometry 中 eyes/chin/orientation/hair_boundary_confidence 保留 null，避免把 Haar 框推导成虚构关键点。
头框由比例先验扩张脸框，真实头发可能超出估计范围。额外几何检查用于标记源图缺失头部和矩形容纳失败，不能独立证明裁剪正确。

## 真实失败与工程调整

* 同一 NASA 图放大到 2048×2048 后，基线检测了 3 个脸框（包含误检）。系统未选最大脸静默出图，返回 REVIEW + 可视化，要求人工矩形。
* 空白图没有脸框，返回 REVIEW，不输出 JPEG；损坏 JPEG 返回 FAIL。
* 合成卡通也能触发 Haar 检测，证明模型输出不能作为真人检测/裁剪准确性的证据。
* 高熵 1000×1000 测试发现 Pillow 11.3 的 optimize=True 内存编码触发 `broken data stream`。改用普通 Huffman 编码避免该路径，再逐个质量编码验证实际字节。尺寸、下限与大小冲突时返回 FAIL，不降像素冒充满足要求。
* Gradio 默认主题含 Google 在线字体；已改用系统字体，关闭 analytics 与 Hugging Face telemetry，并显式 share=False。

## 未完成的准确率评估

几何方案对比分割辅助方案：当前仅完成几何基线。没有模型权重、独立标注和代表集，不能给出分割改进幅度或将它定为生产实现。

头部定位误差、真实剪发率、裁剪一致性、人工修正时间、假 PASS 率均未测定。
本版本自动 PASS 数为 0；不能用此结果宣称准确率 100% 或假 PASS 风险已经解决。
误通过指标应明确分母：错误裁剪中被标为 PASS 的比例；同时报告 PASS 集中的错误比例。没有人工正确/错误标签时两个指标都报告“未知”。
下一步由独立人工标注 head_left/top/right/bottom、crop_correct、hair_clipped、修正耗时；至少 30–50 张、按人划分开发和测试集，冻结参数后运行。

## 测量边界

实测版本和硬件读数见 environment.json；逐图墙钟、CPU 秒和输出字节见 preliminary-results.json。
使用一名 CPU worker、OpenCV 一个线程，无 GPU。RSS 以 psutil 每 10ms 采样，包含解释器/模型/图片处理，不含 UI；容器 RAM 读数不代表其他宿主机。
没有 8GB MacBook Air、Windows、Colab 或 GPU 实测；没有批处理并发、内存压力恢复、掉电断点恢复测试。

界面通过本地 HTTP 上传真实样例，再执行处理和下载；远程 socket 被 guard 拦截。范围与结果见 ui-offline-smoke.json。
未抓取浏览器网络包，不声明完整网络隔离。
