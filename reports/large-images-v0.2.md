# v0.2：大图输入与 15 KB 更新报告

## 范围与行为

输入默认最高 40,000,000 像素，单文件仍最多 33,554,432 字节；超过任一限制会拒绝，错误说明附实际像素与上限。工作图默认最高 24,000,000 像素，不放大，不改写原文件。YAML 使用 `max_pixels`（输入）和 `max_working_pixels`（工作图）两个字段。

只有超过工作图上限才预先缩小。先检查文件头，再解码、等比例 LANCZOS 缩小，之后执行 EXIF 方向校正和颜色转换，避免把全尺寸图反复复制。最终裁剪、输出尺寸、JPEG 编码、质量下限及脸/头估计策略保持原有含义。工作图限制可下调，当前受验证范围最高为 24MP；输入限制最高为 40MP。

结果新增 `image_info`：原始编码尺寸、EXIF 校正后原图尺寸、解码尺寸、工作图尺寸、预览尺寸、两个轴的缩放比例、是否缩小和是否原生降低 JPEG 解码尺寸。公开的 `geometry`、`crop` 和人工矩形仍统一使用 EXIF 校正后的原图坐标，工作坐标不混入对外接口。

界面显示尺寸转换情况和 15 / 20 / 30 / 50 / 100 KB 选项，默认仍为 50 KB。1 KB = 1024 字节，因此 15 KB = 15,360 字节；如果接收机构要求 15,000 字节，需通过配置 `max_kb`/编码器字节策略的后续扩展精确满足，不能把两个单位等同。当前质量下限 65，不会自动突破下限或降低输出尺寸来满足 15 KB；无法满足时返回 FAIL，没有可下载的违规 JPEG。

## 内存边界

工作图 24MP **不是解码器或进程内存的上限**。JPEG draft 只能原生按 1/2、1/4、1/8 等倍率缩小；29MP/40MP 到 24MP 的幅度通常不足以启用它，仍需先解码。PNG 通常需要完整解码。实现保留解压炸弹检查，提前拦截过大输入，并在正常/异常结束时关闭图片对象。

未实现内存压力监控、自适应并发、批处理或中断恢复。这次仍为单图、单个并发处理 worker，不承诺避免所有 OOM。

## 已执行验证

* 46 项 pytest 测试通过，覆盖输入/工作限制、真正的 4480×6536 JPEG、8000×5000 JPEG/PNG、超过 40MP 时在像素解码前拒绝、JPEG 原生降采样、EXIF 旋转坐标、手工裁剪映射、透明度和 sRGB、原图 SHA-256 不变、15 KB 成功/不可达情况。
* 冻结 v0.1 的宇航员输出作回归对照：小图裁剪矩形、JPEG 量化表、输出解码像素和 DPI 相同。ICC 中的生成日期可能不同，因此不能承诺整个 JPEG 文件哈希相同。
* 真实 Gradio HTTP 服务完成上传、处理和下载测试，包含 29MP 合成纯色输入、原图坐标人工矩形和 15 KB 输出；该纯色用例仅验证接口/压缩，不验证人像准确性。输出 4603 字节。Python socket guard 未记录远程连接尝试。见 ui-offline-smoke-v0.2.json。
* Colab、Mac、Windows 未在本次环境实机执行。用户之前报告的 Colab iframe 下载 502 **没有宣称已修复**，升级说明保留原生下载方式。

## 画质与检测限制

对超过 24MP 的真实公共 NASA 肖像，用同一个人工原图矩形，对比“先缩小工作图”与“全尺寸直接裁剪”的结果：输出都是 295×413、JPEG 质量 90。RGB 平均绝对差约 1.478/255，PSNR 约 39.63 dB。见 large-manual-reference.json。

这是单张公共照片的重采样数值对比，不是人眼满意度证明或头发保留率。没有用户那张私人照片，也没有独立人工参考集，仍需要用户比较自己的照片。自动结果继续 REVIEW。

真实公共照片的自动检测测试还出现多脸框（误检），没有生成自动裁剪 JPEG，仍需人工矩形；见 large-public-inputs.json。大图支持并未改善 Haar 的小脸/全身/复杂背景准确率。

资源压力测试使用同一张 512×512 NASA 样例拉伸到指定尺寸；这些构造图片仅用于尺寸与内存验证，不作为真实高分辨率精细人像，也不用于准确率统计。40MP 构造图的 Haar 检测还存在错检背景区域的案例，系统仍标 REVIEW；不能用输出成功证明裁剪正确。

## 复现

```bash
python -m pytest -q
python tools/benchmark_large_images.py
python tools/ui_offline_smoke.py
```

前两个构造大图的测试使用公开包内样例。真实公共 NASA 原图没有打入项目 ZIP；其 URL、尺寸和哈希见 large-input-source-notes.json。可自行下载后运行 `python tools/benchmark_large_images.py --images 原图.jpg`。做人工矩形数值比较时加 `--manual-crop 左 上 右 下`，不会验证人工框本身是否正确。
